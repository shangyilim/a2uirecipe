How our A2UI Python ADK Agent, Vite Dev Proxy, and React Culinary Renderer fit together, traced through a single culinary request.

Generating UI in Our Recipe Assistant

A2UI lets our Python ADK agent describe interactive culinary interfaces as a stream of JSON messages that the React client renders with native Tailwind widgets. Below is the exact architecture of our workspace (recipe_agent/ + frontend/), followed by a step-by-step trace of how user prompts turn into interactive recipe summary cards, ingredient checklists, and local step timers.

Local Reactivity vs. Agent Actions

• Local Reactivity: Timer countdown and Next/Previous carousel run locally in React with zero network latency.
• Agent Actions: "View Details" or "Finish Cooking" dispatches follow-up prompts to the ADK agent.

Step-by-Step Culinary Pipeline Execution

Here is how a request like "I have pasta and eggs, what can I make?" moves through our system from catalog definition to the live native React UI:

1. Define the Catalog (recipe_agent/catalog.py)

We declare custom Pydantic components derived from ComponentCommon, grouped under CULINARY_CATALOG_ID.

recipe_agent/catalog.py (Backend Pydantic) 
class RecipeSummaryCardComponent(ComponentCommon):
    recipeId: Optional[str] = None
    name: DynamicString = Field(description="Title of the recipe")
    prepTime: Optional[DynamicString] = None
    cookTime: Optional[DynamicString] = None
    calories: Optional[DynamicString] = None
    imageUrl: Optional[DynamicString] = Field(description="Relative URL e.g. /images/carbonara.jpg")

def create_culinary_catalog() -> Catalog:
    return Catalog(
        catalogId=CULINARY_CATALOG_ID,
        components=list(BASIC_COMPONENTS) + CULINARY_COMPONENTS,
        functions=create_basic_catalog_functions(),
    )

2. Generate the Skill & Instructions

A2uiRequestProcessor compiles ~44 KB of JSON Schemas directly from create_culinary_catalog() and wraps them into A2uiInstruction.

3. Tool Execution & Backend Validation

The agent calls get_recipes() to retrieve authentic recipes. Then Gemini calls send_a2ui_json_to_client with the A2UI v1.0 JSON payload. create_turn_processor() binds a fresh RendererState(catalogs) on every turn, enforcing that every response contains its own self-contained createSurface.

4. Messages on the Wire (A2UI v1.0 JSON)

The client receives strict A2UI v1.0 messages inside the tool response:

validated_a2ui_json (Wire Protocol) 
[
  {
    "createSurface": {
      "surfaceId": "recipe_catalog_surface_carbonara",
      "catalogId": "https://a2ui.org/specification/v1_0/catalogs/culinary/catalog.json"
    }
  },
  {
    "updateComponents": {
      "surfaceId": "recipe_catalog_surface_carbonara",
      "components": [
        {
          "id": "card_1",
          "component": "RecipeSummaryCard",
          "recipeId": "pasta-carbonara",
          "name": "Authentic Spaghetti Carbonara",
          "cookTime": "20 mins",
          "calories": "540 kcal",
          "imageUrl": "/images/carbonara.jpg"
        }
      ]
    }
  }
]

5. Client-Side Rendering (frontend/src/catalog/culinaryCatalog.tsx)

The frontend registers matching Zod schemas and binds React components via createComponentImplementation.

6. Handling User Actions (Local vs. Agent Actions)

Architectural Invariant: Single-Card Cooking Bundling
In GuidedCookingCard.tsx, all cooking steps are sent at once. The user can click Next / Previous or start the CookingTimer locally without any LLM latency or network requests! Clicking "Finish Cooking" dispatches an agent action to celebrate and plan dessert.
